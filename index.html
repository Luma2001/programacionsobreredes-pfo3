Descripción del Proyecto

Evolución de un sistema monolítico tradicional hacia una arquitectura cliente-servidor distribuida. El servidor socket implementa un ThreadPoolExecutor para desacoplar y balancear el procesamiento concurrente de tareas, garantizando entrega confiable y control de saturación.

Monolito (PFO 2) vs. Sistema Distribuido (PFO 3)

Criterio PFO 2 (Monolítico) PFO 3 (Distribuido)
Protocolo HTTP / REST (Sin estado, petición-respuesta) TCP Sockets (Canal persistente y orientado a conexión)
Concurrencia Manejada por el servidor web integrado de Flask Pool dedicado de hilos reutilizables (ThreadPoolExecutor)
Persistencia Base de datos local en disco embebido (SQLite) PostgreSQL (ACID) y Amazon S3 (Almacenamiento de objetos)
